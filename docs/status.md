**Hosting turned into the real story of this round.** This sandboxed dev tool cannot keep a persistent Node process alive with working outbound network access — confirmed broken four separate ways, each fully reproduced before moving on: a Python `subprocess.Popen(start_new_session=True)` detached process, the harness's own `run_in_background` task (both via `npm start` and bare `npx tsx`), and a macOS `launchd` user agent spawned entirely outside this tool's process tree. All four connect to nothing and sit silently with zero network sockets, zero errors, indefinitely. Only a blocking foreground shell command ever worked. Root-caused this is not a hosting-sandbox restriction (a plain `curl` backgrounded the same way worked fine) — it's specific to this long-running Node/tsx process; the actual mechanism was never fully identified, but reproducing it four ways ruled out "try a different backgrounding trick" as the fix.
